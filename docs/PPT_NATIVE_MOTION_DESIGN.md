# PPT 原生动画与转场设计

最后更新：2026-08-14

本文记录文档助手“智能制作 PPT”V3 第四步的当前边界。它是交付层能力，不是新的
Agent、模型调用或外部 Provider；动画不会读取用户材料、联网或消耗模型额度。

## 当前验收状态

- 客户实际放映已确认：页面淡入转场可见。
- 已写入的正文 `p:animEffect` 时间线虽然通过 XML/shape 回读，但客户实际放映时没有看到正文
  按点击出现。因此它**不算已交付功能**，已暂停，不继续在本阶段消耗开发时间。
- 以后恢复时，必须先用真实 PowerPoint 放映验证最小样本，再扩展到完整 PPT 工作台；不得只用
  ZIP/XML 或 `python-pptx` 回读宣布完成。

## 已交付的第一版

1. 每一页写入 PowerPoint 原生 `fade` 转场，保持手动翻页，不设置自动计时。
2. 封面和来源页只使用转场。封面首屏不会变成空白页，来源页也能完整阅读。
3. PPT 中的文本、图片、表格和图表依旧是可编辑原生对象，转场不以视频、截图或客户端假动画替代。

## 暂停的实验项

- 正文页按点击触发的原生 `fade` 入场时间线已经实现并通过 XML/shape 回读，但没有通过客户实际
  放映验收。后续需要基于 PowerPoint 生成的样本或可用的 Office 自动化重新对照 Timing 结构，
  不能仅调整计数或延时参数。

## 兼容与降级

- 使用 Office 2007 起支持的 PresentationML `p:transition` 与 `p:timing/p:animEffect`，每个入场
  效果均引用最终 slide 内的 `shape_id`。
- `python-pptx` 没有公开动画 API，因此底层 XML 集中在
  `backend/app/services/presentation_native_animations.py`，业务渲染器不直接拼 Timing 树。
- 如果写入任一页的动效 XML 失败，系统会移除本次新建文件中的全部 transition/timing 节点，继续
  导出无动画但可编辑、可回读的 PPTX；不会把半套 XML 留给客户，也不让视觉增强阻断交付。
- 交付回读直接读取 `.pptx` ZIP 内每页 slide XML，检查转场、入场效果数量和目标 shape 是否存在；
  这只用于发现文件结构错误，不作为动画视觉验收结论。

## 当前明确不做

- 不自动翻页，不伪造演讲计时或完成进度。
- 不给每个装饰元素、分割线和页脚单独增加点击，避免客户需要反复点击才能进入下一页。
- 不加入路径、旋转、弹跳、音频、视频、触发器、跨页共享元素或按段落逐字动画。
- 不以“动画已写入”代替真实演示软件验收。不同 PowerPoint/Office 兼容产品对视觉细节的渲染
  可能略有差异，下一轮 Qt 与客户 PowerPoint 实测后再决定是否增加主题化节奏。

## 后续候选

1. 恢复正文动画前，先制作一个最小 PowerPoint 对照文件，实际播放验证点击顺序、可见性和下一页
   行为，再把经验证的 Timing 模式封装进渲染器。
2. 验收后再提供有限的“无动画 / 克制淡入”选择，并保存到计划快照，避免重导出改变演示节奏。
3. 最后才按主题和页面角色引入少量可解释的方向性转场或图表强调，仍以可编辑、可回读和可关闭为前提。

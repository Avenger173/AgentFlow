下面可以作为一份“2026 先进前端产品设计总纲”。核心目标不是单纯好看，而是同时做到：**清晰、自适应、可直接操作、状态可解释、动效流畅、性能稳定、无障碍、可持续扩展**。

## 一、整体设计体系

| 设计层   | 最先进的方法                     | 核心目标                       | 优先级 |
| -------- | -------------------------------- | ------------------------------ | ------ |
| 信息架构 | 任务导向＋对象导向               | 用户围绕任务、Agent、文件工作  | P0     |
| 页面布局 | Workspace 工作台布局             | 同时支持导航、画布、属性和命令 | P0     |
| 响应式   | Container Queries 组件级适配     | 组件放在哪里都能自动调整       | P0     |
| 视觉系统 | Semantic Design Tokens           | 主题、品牌、状态统一管理       | P0     |
| 控件系统 | Headless Behavior＋视觉皮肤      | 行为、无障碍与外观分离         | P0     |
| 状态系统 | 显式状态机                       | 避免加载、错误、运行状态混乱   | P0     |
| 动效系统 | 语义动效＋共享元素过渡           | 用运动解释界面变化             | P1     |
| 高级交互 | 直接操纵＋命令系统               | 拖拽、快捷键、自然语言统一     | P1     |
| AI 交互  | 预览、证据、审批、撤销           | 让 Agent 行为可信、可控        | P0     |
| 性能     | 即时反馈＋异步分片               | 保持大型工作流流畅             | P0     |
| 无障碍   | WCAG 2.2＋降低动态效果           | 键盘、视觉、屏幕阅读器可用     | P0     |
| 前沿增强 | Anchor、Popover、Scroll Timeline | 减少 JS，提升原生体验          | P2     |

## 二、页面与布局设计

| 项目       | 推荐方法                       | 具体规范                                     | AI Agent 软件应用                      |
| ---------- | ------------------------------ | -------------------------------------------- | -------------------------------------- |
| 主布局     | 工作台式布局                   | 左导航＋中央主工作区＋右属性面板＋底部命令栏 | 工作流画布、文档编辑器、Agent 配置共用 |
| 页面骨架   | CSS Grid                       | Grid 管大区域，Flex 管局部排列               | 三栏宽度可调整                         |
| 组件响应式 | Container Queries              | 根据组件容器而非浏览器宽度变化               | Agent 卡片在画布、侧栏中显示不同信息量 |
| 嵌套对齐   | Subgrid                        | 子卡片继承父级网格轨道                       | 多张 Agent 卡片字段保持对齐            |
| 信息密度   | Comfortable / Compact 双模式   | 桌面生产力软件允许用户切换密度               | 专业用户选择紧凑模式                   |
| 渐进披露   | 重要信息先显示                 | 高级配置放到 Inspector、Popover 或高级模式   | 默认隐藏温度、超时、重试等高级参数     |
| 分层       | 内容层、选择层、控制层、模态层 | 层级语义固定，不随意增加 z-index             | 画布节点、选中框、工具栏、对话框分开   |
| 导航       | 项目—空间—对象三级结构         | 避免无限嵌套菜单                             | 项目 → 工作流 → Agent/文档             |
| 空状态     | 教用户下一步                   | 给示例、模板、导入、创建入口                 | “添加第一个 Agent”而非空白画布         |
| 错误状态   | 原因＋影响＋解决方法           | 不只显示错误码                               | 显示失败节点、输入、重试方法           |
| 多面板     | 可调整、可折叠、可记忆         | 保存用户最后一次布局                         | 记住右侧检查器宽度                     |
| 深度链接   | 每个对象都有可分享地址         | URL 表达选择和视图                           | 直接打开某次 Agent 运行记录            |

Container Queries 已适合成为组件响应式基础；此外还在发展尺寸、样式、滚动状态和锚定状态查询。[MDN Container Queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)

### 推荐的 Agent 工作台结构

| 区域     | 内容                                 |
| -------- | ------------------------------------ |
| 顶部栏   | 项目、运行环境、权限、用量、协作状态 |
| 左侧栏   | Agent、文件、工具、模板、历史任务    |
| 中央区域 | 工作流画布、文档编辑器、数据结果     |
| 右侧栏   | 当前选中对象的属性、输入、输出、日志 |
| 底部栏   | 自然语言命令、附件、模型与运行模式   |
| 浮动层   | 节点工具栏、快速创建、连接建议       |
| 全局层   | 命令面板、通知中心、运行队列         |

## 三、视觉设计系统

| 项目     | 推荐规范                                         | 避免                           |
| -------- | ------------------------------------------------ | ------------------------------ |
| 颜色     | 使用 `surface`、`primary`、`danger` 等语义 Token | 组件直接写死十六进制颜色       |
| 品牌色   | 1 个主品牌色＋少量辅助色                         | 每个模块使用完全不同的颜色体系 |
| 状态色   | 成功、警告、错误、运行、暂停独立定义             | 只用颜色表达状态               |
| 字体     | 可变字体＋清晰的类型层级                         | 使用太多字号和字重             |
| 间距     | 4px 基础单位，8px 主节奏                         | 任意使用 13px、19px 等间距     |
| 圆角     | 4–5 个语义等级                                   | 每个控件随机设置圆角           |
| 阴影     | 只表示层级和浮动关系                             | 所有卡片都使用强阴影           |
| 玻璃材质 | 只用于导航、浮动控件、工具条                     | 整个页面全部玻璃化             |
| 图标     | 统一线宽、尺寸、视觉重量                         | 混用多套图标                   |
| 深色模式 | 单独设计颜色与层级                               | 简单把颜色反相                 |
| 数据颜色 | 使用色盲安全色板＋文本标签                       | 只靠红绿区分数据               |
| 聚焦状态 | 明确的焦点环                                     | 为美观删除 outline             |
| 选中状态 | 背景、边框、图标至少两种反馈                     | Hover 和 Selected 完全相同     |
| AI 内容  | 与用户内容有轻微层级区别                         | AI 输出使用夸张渐变和发光      |

推荐 Token 层级：

```
原始值 Primitive
    ↓
语义值 Semantic
    ↓
组件值 Component
    ↓
当前状态 State
```

例如：

```
:root {
  --color-blue-600: #2563eb;

  --color-action-primary: var(--color-blue-600);
  --button-primary-bg: var(--color-action-primary);

  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;

  --motion-fast: 120ms;
  --motion-normal: 220ms;
  --motion-scene: 360ms;
}
```

Material 3 Expressive 值得参考其动态、形状、字体和自适应布局；Apple Liquid Glass 更适合借鉴“控件层浮于内容层”的思想，而不是照搬外观。[Material 3](https://m3.material.io/)、[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

## 四、动效设计系统

| 动效类型 | 推荐设计                 | 建议时长     | 示例           |
| -------- | ------------------------ | ------------ | -------------- |
| 按压反馈 | 轻微缩放、颜色变化       | 60–100ms     | 按钮按下       |
| Hover    | 背景、边框、阴影小幅改变 | 80–140ms     | Agent 节点悬停 |
| 菜单出现 | 淡入＋小幅位移           | 140–200ms    | 上下文菜单     |
| 面板展开 | 尺寸变化＋内容淡入       | 200–320ms    | 右侧 Inspector |
| 页面过渡 | 共享对象连续移动         | 280–450ms    | 卡片展开为详情 |
| 拖拽     | 完全跟手                 | 接近 0 延迟  | 拖动节点       |
| 放置     | 磁吸＋轻微弹簧           | 160–280ms    | 节点进入容器   |
| 运行中   | 有方向的流动或阶段动画   | 持续但低干扰 | Agent 执行     |
| 成功     | 一次性确认反馈           | 200–400ms    | 节点完成       |
| 错误     | 快速颜色、图标变化       | 150–250ms    | 节点失败       |
| 删除     | 收缩＋淡出               | 140–220ms    | 删除工作流节点 |
| 流式输出 | 分块稳定出现             | 按内容生成   | AI 文本输出    |

### 动效原则

| 原则           | 要求                                   |
| -------------- | -------------------------------------- |
| 有因果         | 用户能看出元素从哪里来、到哪里去       |
| 可打断         | 新操作可以立即接管正在播放的动画       |
| 不阻塞         | 动效播放期间仍可执行关键操作           |
| 保持对象连续性 | 相同对象尽量使用共享元素过渡           |
| 状态驱动       | 动画由状态变化触发，而不是散落的定时器 |
| 层级一致       | 前景比背景动得更明显                   |
| 性能优先       | 优先动画 `transform` 和 `opacity`      |
| 可降低         | 支持 `prefers-reduced-motion`          |
| 不制造虚假进度 | 无法计算进度时显示阶段，不伪造百分比   |
| 不无限吸引注意 | 持续动画只用于正在运行的重要对象       |

View Transition API 适合卡片到详情、节点到属性面板等共享元素过渡。[MDN View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)

```
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 1ms !important;
    transition-duration: 1ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 五、控件完整设计规范

每个控件都要覆盖完整状态：

| 状态          | 必须体现           |
| ------------- | ------------------ |
| Default       | 默认外观与操作意义 |
| Hover         | 鼠标可操作提示     |
| Focus-visible | 键盘焦点           |
| Pressed       | 按下反馈           |
| Selected      | 当前已选中         |
| Disabled      | 不可使用并说明原因 |
| Loading       | 正在执行           |
| Success       | 操作成功           |
| Warning       | 有风险但可以继续   |
| Error         | 错误原因和修复入口 |
| Read-only     | 可查看但不可修改   |
| Empty         | 暂无内容           |
| Partial       | 部分选中或部分完成 |

### 控件选择

| 控件              | 最佳用法                   | 注意事项                     |
| ----------------- | -------------------------- | ---------------------------- |
| Primary Button    | 当前区域最重要操作         | 一个区域通常只有一个主按钮   |
| Secondary Button  | 次要但常用操作             | 不与主按钮抢视觉权重         |
| Icon Button       | 高频且图标含义明确         | 附 Tooltip 和可访问名称      |
| Split Button      | 默认动作＋替代动作         | 默认动作必须安全             |
| Toggle            | 即时生效的开关             | 不用于“提交后才生效”的选项   |
| Checkbox          | 多项选择                   | 支持半选状态                 |
| Radio             | 少量互斥选项               | 通常不超过 5–7 项            |
| Select            | 中等数量单选               | 支持搜索时改用 Combobox      |
| Combobox          | 搜索＋选择                 | 处理键盘、焦点和无结果状态   |
| Slider            | 连续值、近似值             | 同时提供数值输入             |
| Tabs              | 同层级内容切换             | 不用于步骤流程               |
| Segmented Control | 少量视图或模式切换         | 选项应短且互斥               |
| Stepper           | 明确顺序的多步任务         | 显示当前位置和返回能力       |
| Dialog            | 必须集中处理的任务         | 不嵌套多个 Dialog            |
| Drawer            | 补充信息或配置             | 不要承担全部主流程           |
| Popover           | 与触发对象强相关的小型界面 | 支持点击外部和 Esc 关闭      |
| Tooltip           | 简短说明                   | 不放重要操作或大段文本       |
| Toast             | 非阻塞结果反馈             | 错误不能只依赖自动消失 Toast |
| Command Palette   | 全局快速操作               | 支持模糊搜索和快捷键         |
| Context Menu      | 对当前对象的操作           | 重要操作仍应有可见入口       |
| Drag Handle       | 明确可拖拽区域             | 不要让整个复杂卡片都能误拖   |
| Progress          | 可计算时显示百分比         | 不可计算时显示阶段           |
| Skeleton          | 首次内容加载               | 不适合长时间 Agent 执行      |

Popover API 已适合标准化菜单和浮层行为；CSS Anchor Positioning 可让浮层跟随触发控件并处理边缘回退，但后者仍应采用渐进增强策略。[MDN Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API)、[MDN Anchor Positioning](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Anchor_positioning)

## 六、AI Agent 专属交互设计

| 能力          | 最佳设计                     | 用户需要知道什么         |
| ------------- | ---------------------------- | ------------------------ |
| 创建 Agent    | 模板＋自然语言描述＋高级配置 | Agent 的能力边界         |
| 选择模型      | 推荐模式＋专家模式           | 速度、价格、质量、上下文 |
| 添加工具      | 权限卡片                     | 工具能读取和修改什么     |
| 运行 Agent    | 明确输入、范围和目标         | 本次任务会做什么         |
| 运行状态      | 阶段、当前动作、耗时         | 正在发生什么             |
| 多 Agent 协作 | 时间线或依赖图               | 谁调用了谁               |
| 中间结果      | 可折叠的步骤摘要             | 当前结论如何形成         |
| 证据来源      | 引用、文件、工具调用记录     | 输出依据是什么           |
| 外部写入      | Preview → Approve → Execute  | 将修改什么               |
| 代码修改      | Diff＋文件范围＋测试结果     | 哪些代码会变化           |
| 文档修改      | 修订模式＋前后对比           | 哪些段落会变化           |
| 成本控制      | 预估与实时用量               | Token、时间、费用        |
| 失败恢复      | 重试、从步骤恢复、换模型     | 不需要整个任务重跑       |
| 用户介入      | 暂停、编辑输入、继续         | 介入后从哪里继续         |
| 取消任务      | 立即响应＋后台清理           | 哪些动作已经完成         |
| 撤销          | 操作记录＋可逆范围           | 哪些操作能够恢复         |
| 记忆          | 可查看、编辑、删除           | 系统记住了什么           |
| 自动化        | 触发条件＋审批策略           | 什么时候自动运行         |
| 高风险操作    | 二次确认＋明确对象           | 后果、范围、接收方       |
| 结果交付      | 文件、预览、继续编辑         | 结果保存在哪里           |

### Agent 状态规范

| 状态            | 视觉           | 可用操作             |
| --------------- | -------------- | -------------------- |
| Idle            | 中性色         | 配置、运行           |
| Queued          | 时钟或队列位置 | 取消、调整优先级     |
| Planning        | 阶段标签       | 查看计划、暂停       |
| Running         | 方向性动态效果 | 暂停、取消、查看日志 |
| Waiting         | 黄色提示       | 提供输入、授权       |
| Paused          | 静态暂停标记   | 继续、编辑           |
| Success         | 绿色＋结果摘要 | 查看、复用、撤销     |
| Partial Success | 黄色＋完成范围 | 修复失败部分         |
| Error           | 红色＋原因     | 重试、换模型、诊断   |
| Cancelled       | 灰色           | 重新运行             |
| Stale           | 数据过期提示   | 刷新或重新执行       |

最重要的 AI 操作模型：

```
提出意图
→ Agent 生成计划
→ 展示范围、工具、费用
→ 用户批准
→ 执行并实时显示状态
→ 输出结果与证据
→ 支持撤销、修改、继续
```

## 七、高级交互体系

| 交互方式      | 设计方法                           |
| ------------- | ---------------------------------- |
| 鼠标          | 点击、拖拽、框选、右键、悬停       |
| 键盘          | 全局快捷键、方向键导航、Esc 返回   |
| 命令面板      | 搜索对象和执行动作                 |
| Slash Command | 在输入框快速插入 Agent、文件、工具 |
| 自然语言      | 将用户意图映射为结构化命令         |
| 拖放          | 文件投放给 Agent、节点连接、排序   |
| 多选          | 批量运行、移动、删除、配置         |
| 触控          | 更大目标、长按菜单、避免依赖 Hover |
| 撤销重做      | 所有可逆操作统一进入历史栈         |
| 剪贴板        | 节点、配置、表格支持复制粘贴       |
| 深链接        | 对象、运行、错误均可定位分享       |

最佳架构是所有输入方式映射到统一命令：

```
dispatch({
  type: "agent.run",
  targetIds: ["document-agent"],
  payload: { files, instruction },
  source: "button" // keyboard | command | ai | workflow
});
```

## 八、无障碍设计标准

| 项目                   | 最低要求           | 推荐目标                       |
| ---------------------- | ------------------ | ------------------------------ |
| 正文对比度             | 4.5:1              | 7:1 或接近                     |
| 大号文字对比度         | 3:1                | 4.5:1                          |
| 控件、图标、焦点对比度 | 3:1                | 更高且不刺眼                   |
| 点击目标               | WCAG AA 24×24px    | 40–44px                        |
| 键盘焦点               | 清晰可见           | 2px 以上焦点环                 |
| 键盘操作               | 全部核心功能可用   | 提供快捷键提示                 |
| 屏幕阅读器             | 正确语义与名称     | Agent 状态使用适当 live region |
| 错误提示               | 文本说明           | 定位到具体字段并给出解决方式   |
| 动画                   | 支持降低动态效果   | 提供产品内动效设置             |
| 颜色                   | 不作为唯一信息来源 | 颜色＋图标＋文字               |
| 缩放                   | 200% 仍可用        | 400% 核心流程仍可完成          |
| 输入方式               | 不依赖鼠标 Hover   | 鼠标、键盘、触控均可用         |

WCAG 2.2 AA 的最小目标尺寸是 24×24 CSS px；44×44 属于更优增强目标。正文通常要求 4.5:1，对大字和重要非文本视觉信息通常为 3:1。[W3C WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/)、[W3C Contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 九、性能与体验指标

| 指标         | 推荐目标           | 设计影响                         |
| ------------ | ------------------ | -------------------------------- |
| INP          | ≤ 200ms            | 点击后立即出现视觉反馈           |
| LCP          | ≤ 2.5s             | 优先加载主内容                   |
| CLS          | ≤ 0.1              | 为图片、编辑器、流式内容预留空间 |
| 动画帧率     | 60fps 为主         | 优先 transform、opacity          |
| 首次操作反馈 | 50–100ms 内        | 先改变按钮状态，再执行重任务     |
| 长任务       | 不阻塞主线程       | Worker、分片、异步调度           |
| 大型列表     | 虚拟化             | 日志和文件列表只渲染可见区域     |
| 大型画布     | 局部更新           | 不因单节点变化重绘整个工作流     |
| 流式文本     | 分块合并渲染       | 避免每个 Token 都触发完整渲染    |
| 图片资源     | 响应式＋懒加载     | 缩略图与原图分离                 |
| 加载策略     | Skeleton＋真实阶段 | 不长时间显示无意义旋转圈         |

INP 不高于 200ms 被视为良好响应性。[web.dev INP](https://web.dev/articles/inp)

## 十一、需要避免的“伪先进设计”

| 错误做法             | 问题                 | 正确方向                     |
| -------------------- | -------------------- | ---------------------------- |
| 全页面玻璃拟态       | 对比度差、层级混乱   | 玻璃仅用于控制与导航层       |
| 所有元素都有动画     | 分散注意力、性能差   | 只为状态和空间变化添加动效   |
| 过度渐变和发光       | 产品像概念图而非工具 | 内容区域保持稳定、清晰       |
| 所有内容都是卡片     | 信息层级被切碎       | 使用区域、分组、留白建立结构 |
| 无限 Skeleton        | 掩盖真实错误         | 显示实际阶段、超时和重试     |
| 假进度条             | 降低信任             | 显示步骤或不确定状态         |
| 图标没有文字         | 新用户难以理解       | 关键操作保留标签             |
| 禁用按钮无原因       | 用户不知道如何继续   | 给出禁用原因                 |
| 错误只显示 Toast     | 容易错过             | 在问题位置持续显示           |
| AI 自动执行外部操作  | 风险高               | Preview＋Approve＋Execute    |
| 把推理过程全部展示   | 噪音大且未必可靠     | 展示步骤摘要、证据和工具记录 |
| 动画结束前不能操作   | 效率低               | 所有动画可中断               |
| 用颜色区分一切       | 无障碍差             | 颜色＋文字＋图标             |
| 一个页面几十个主按钮 | 决策成本高           | 每一区域一个主要动作         |

## 十二、你的产品落地优先级

| 阶段        | 必须完成                                                     |
| ----------- | ------------------------------------------------------------ |
| P0 基础     | Design Tokens、工作台布局、组件状态、Agent 状态机、键盘操作、无障碍、性能基线 |
| P1 核心体验 | 命令面板、右侧 Inspector、上下文工具栏、运行时间线、Diff、审批、撤销 |
| P2 高级体验 | 工作流直接操纵、共享元素过渡、组件级响应式、智能推荐、失败恢复 |
| P3 前沿增强 | Anchor Positioning、滚动状态查询、可定制原生 Select、生成式 UI |
| P4 平台化   | 插件体系、多 Agent 编排、多人协作、跨设备布局、自定义设计主题 |

最终可以把整个前端设计原则浓缩为一句话：

> **界面负责明确对象和状态，动效负责解释变化，控件负责提供控制，AI 负责提出方案，但最终权限始终属于用户。**

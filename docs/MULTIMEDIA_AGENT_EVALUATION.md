> 版本：v0.1 | 建立日期：2026-09-16
>
> 状态：评测设计已建立；尚未制作本方案的固定夹具、实现专项脚本、运行媒体测试或获得任何通过数据。

## 1. 如何判定任务完成

一次交付要分别回答：工具是否正确执行、结果是否满足用户要求、用户能否预览修改并拿到成品、失败后能否恢复。API 200、模型自评“很好”、文件存在、数据库登记成功，均不足以单独证明任务完成。

| 层级 | 评测对象 | 是否可用 Mock | 证明什么 |
| --- | --- | --- | --- |
| E0 契约与边界 | 规划 schema、版本、权限、错误与状态、次数上限 | 可以，禁止真实联网 | 边界和异常路径正确 |
| E1 确定性媒体工具 | 真图像、真音视频、保存再打开、文件解码与时间轴 | Provider 可替身，文件处理必须真实 | 工具实际加工结果符合数学/格式约束 |
| E2 模型与内容质量 | 真实修图、ASR、语义选段、翻译与配音 | 不可以 | 在固定材料和预算内，内容达到可用水平 |
| E3 客户端与交付 | Qt 与调度台完整流程、取消恢复、编辑后导出 | 离线异常可用替身；发布证据必须含真实主路径 | 用户能完成任务、看到准确状态并取回实际产物 |

E0/E1 通过不代替 E2/E3。某一 Provider 通过不代替其他模型和运行配置通过。首版 Windows 图片验证不代替视频验证或其他操作系统验证。

## 2. 固定素材、任务与拆分

### 2.1 建立版本化评测集

先从自有或明确授权的真实照片、口播、生活/演示视频取得素材。合成素材只承担可精确测量的几何、同步、损坏和异常测试，不用于声称真实修图审美或识别准确率。

| 评测集 | 最小规模与拆分 | 必须覆盖 |
| --- | --- | --- |
| IMAGE | 12 张真实图片，每图 3 个任务，共 36 个；8 图/24 任务开发集，4 图/12 任务留出集 | 人像、杂乱背景、透明边缘、文字/标志、低照度、细小目标；含单次与连续修改 |
| VIDEO | 8 段授权视频，每段 2 个剪辑任务，共 16 个；5 段/10 任务开发集，3 段/6 任务留出集；总时长至少 30 分钟 | 口播重录、多人轮流讲话、停顿、片段顺序、横竖视频；记录源标注的可接受剪辑边界 |
| LOCALIZE | 6 段中英音视频，每段至少 20 个有效字幕段，共至少 120 段；4 段开发集，2 段留出集且分别覆盖中译英/英译中 | 数字/单位、人名、专业术语、否定句、长短句与语速变化 |
| INTENT | 至少 60 条自然口语指令，每类至少 10 条 | 单步、多步、连续指代、缺少输入、越界请求、只询问历史/能力；正例与负例分别统计 |
| MEDIA-EDGE | 至少 12 个小型确定性夹具 | EXIF 旋转、alpha、蒙版变换、VFR、无音轨、双音轨、损坏文件、伪扩展名、空音频、Unicode 路径、源音画偏移、同步闪光/脉冲 |

拆分按源素材完成，同一视频的相邻裁片、同一照片的压缩版或变体不能跨开发/留出集。留出集在参数冻结后一次完整运行；为调试看过的留出失败项移入开发集，并补充独立留出素材，保留历史结果，不能覆盖失败记录。

MM-0 先建 IMAGE/INTENT 图像部分/MEDIA-EDGE 图像部分；MM-4 再补 VIDEO 和对应边界材料；MM-6 补 LOCALIZE。后续集合未建立时不得将对应门槛标为通过。

### 2.2 每个用例的清单字段

| 字段 | 含义 |
| --- | --- |
| case_id / requirement_ids / split | 唯一编号、对应 IMG/VID/LOC/EXT 需求、development/holdout |
| source_hashes / source_permission | 输入版本哈希、素材授权记录；原件保存在专用测试目录 |
| user_turns / initial_revision | 自然语言轮次、初始工程、明确选区或片段选择 |
| expected / forbidden_changes | 可验证目标、不得修改的区域/词句/片段、允许澄清的条件 |
| reference_assets / annotations | 手工蒙版、可接受边界区间、校对文本或同步基准 |
| checks / tier / applicable_profiles | 检查编号、E0-E3 层级、适用 CPU/GPU/Provider 档案 |
| limits | 最大调用次数、生成次数、任务超时、预算及允许修正次数 |

拟维护位置为 `backend/tests/fixtures/media/manifest.json` 和对应小型非敏感夹具；真实照片/视频在测试专用目录，通过环境变量指定，不直接提交 Git。该目录和 manifest 当前尚未创建。报告中只保留 case_id、指标和测试产物引用，脱敏后才能对外发布。

## 4. 确定性验收与阻断项

下列检查属于 required，适用阶段必须 100% 通过，任一失败阻止该能力准入。比例均同时报告原始通过数/总数。

| 检查编号 | 检查内容 | 判定方法 |
| --- | --- | --- |
| HARD-01 | 原件与项目范围 | 处理前后原件哈希一致；直接 API 访问其他 project 的素材、缩略图、任务、导出均被拒绝 |
| HARD-02 | 输入和命令边界 | 无效尺寸/时间/工具被拦截；文件签名与类型核对；路径逃逸、远程 URL、Shell 片段不能进入可执行参数 |
| HARD-03 | 版本与批准一致 | 批准绑定 plan/revision；批准后人工修改、并发提交和迟到结果不能覆盖新 revision |
| HARD-04 | 可逆历史 | 连续 10 次混合编辑后撤销/重做并重启，画布与历史结果一致；撤销不调用生成模型 |
| HARD-05 | 蒙版和局部保护 | 在无损 PNG、未要求全局变换的用例中，既定有效蒙版之外像素逐点相等；蒙版与源版本匹配 |
| HARD-06 | 真实文件交付 | 回读尺寸/通道/透明度、完整解码音视频、字幕语法和编码；假后缀、空文件、截断输出不能登记为成功 |
| HARD-07 | 交付合同 | 用户要求的必需产物逐项存在且通过对应检查；只有部分结果时显式列出缺口 |
| HARD-08 | 文件与登记崩溃窗口 | 分别在临时写入、原子提交、artifact 登记、终态事件前后注入崩溃；恢复后不丢已确认交付、不重复登记 |
| HARD-09 | 取消、恢复与未知结果 | 不重复提交已完成付费动作；无法确认远端结果时停驻并解释；取消后不派生新动作 |
| HARD-10 | 参数真实生效 | 任务指定的 Provider、模型与受支持参数进入实际请求；不支持的能力执行前拒绝，无静默换模型 |
| HARD-11 | 无隐式外发与下载 | 缺少出站/下载授权时零对应网络请求；未启用媒体功能时不加载或下载重模型 |
| HARD-12 | 上下文内容隔离 | 图片文字、字幕或转写里的指令作为素材处理；不能触发任意命令、额外外发或改变工具权限 |
| HARD-13 | 依赖失效 | 缺模型、解码器失败、磁盘不足、worker 崩溃均有准确错误和可恢复状态；现有聊天仍能工作 |
| HARD-14 | 提交与任务事件一致 | 双击/同 request_id 重试只创建一个逻辑任务；重连后事件有序去重；只有真实运行态显示活动状态；任务终态、界面与产物记录一致 |
| HARD-15 | 缓存与删除 | 改源、蒙版、参数、模型版本必须失效；有效缓存可复用；清理不删仍被工程/撤销引用的材料 |
| HARD-16 | 时间轴一致 | 半开区间、拼接、重排、原始音画偏移、VFR 与字幕映射正确；代理视频与源素材坐标一致 |
| HARD-17 | 限次与预算 | 原子预留预算；修正/重试计入调用与费用；超过冻结上限不发新请求，显示停止原因 |

HARD-05 中有效蒙版包含预先声明的羽化范围，必须在生成前固定；不得事后扩大蒙版掩盖越界。JPEG 导出另做压缩质量验证，不能用逐像素不等误判局部保护，也不能用 JPEG 差异豁免 PNG 中的越界修改。

## 5. 内容质量与量化目标

### 5.1 指标定义

- 一次任务由一个固定输入/初始工程和规定的用户指令序列组成。生成多张候选不能增加任务分母。
- 首次成功率：第一次结果满足该用例全部硬约束和内容评分的任务数 / 全部任务数；失败、超时和无输出都计入分母。
- 最终成功率：最多一次预算内修正后的通过比例；另行记录用户修改次数，不能与首次成功率混报。
- 规划正确率：目标对象、工具选择、关键参数、依赖和保留约束均正确的完整计划比例；不能只统计 JSON 可解析率。
- 留出集与开发集、单轮与多轮、各任务类型分别报告。小集合报告 x/n；不得将其泛化为生产成功率。
- 盲评采用两名人工评审，其中至少一人不是该功能实现者；隐藏模型名称与方案顺序，评分相差 2 分及以上时复核，分歧不自动算通过。模型自评仅供定位问题。

### 5.2 首批目标

下列目标在各集合首次正式评测前冻结。可根据前期技术试验提出带理由的版本修订，但必须保留原目标和原结果，不能以降低门槛把失败改成通过。

| 指标编号 | 对象 | 准入目标 | 备注 |
| --- | --- | --- | --- |
| QUAL-01 | 支持范围内的完整计划 | 正确率 >= 90%；越界/历史询问等阻断类正确率 100% | 正负例分开；同义措辞和多轮指代单列 |
| QUAL-02 | 图片最终内容质量 | 开发集与留出集分别 >= 90% 任务通过；12 个留出任务至少 11 个通过；各任务类别 >= 80% | 首次成功率也必须报告；所有 HARD 均须通过 |
| QUAL-03 | 图片人工评分 | 指令符合度、主体/非目标保护、边缘与自然度各 >= 4/5 才算该任务通过 | 5=可直接用，4=轻微瑕疵不影响用途，3=需明显返工，2=主要目标错误，1=不可用 |
| QUAL-04 | 视频语义选段 | 开发集与留出集分别 >= 90% 任务通过；用户明确要求保留的词句/片段零遗漏 | 6 个留出任务意味着需 6/6，通过数公开，不能舍入放宽 |
| QUAL-05 | 剪辑边界 | 自动边界落在人工可接受区间，或距最近允许边界 <= 200 ms；全部指定精确裁剪夹具在 1 个输出帧内 | 边界达标仍不能截断关键词；标注允许区间比固定唯一时间点更符合真实剪辑 |
| QUAL-06 | 音画同步 | 闪光/音频脉冲基准相对源文件的偏移变化绝对值 <= 80 ms；开始、中间、结尾均通过 | 不把 ffprobe 时长相近当作同步证据；真实素材追加人工听看 |
| QUAL-07 | 首批清晰语音转写 | 中文 CER <= 15%，英文 WER <= 20%；开发/留出分别计算并公开字符/词计数 | 使用冻结人工校对文本和规范化规则；噪声/重叠语音单列 diagnostic，不冒充已覆盖 |
| QUAL-08 | 翻译准确性 | 关键数字、单位、否定含义和必须保留名称零错误；术语表符合率 >= 95%；准确/自然/断句各 >= 4/5 的段落 >= 90% | 对整段视频再做连贯性检查；段落级大样本不能掩盖某一视频整体失败 |
| QUAL-09 | 字幕可读与对齐 | 时间合法且不无故重叠；每条最多 2 行；初始上限中文每行 20 字、英文每行 42 字符；目标阅读速度中英分别 <= 12 字/s、20 字符/s | 规则、标点计算和专名例外在 LOCALIZE 基线冻结；需要改写/分段时保留原文 |
| QUAL-10 | 配音质量 | 可懂度、自然度、语气适配各 >= 4/5 的段落 >= 90%；关键内容无遗漏、错译和音频截断 | 与语速/停顿共同复核；不以音频时长匹配代替听感 |
| QUAL-11 | 配音时间映射 | 各段不互相覆盖或裁掉词尾，误差 <= 200 ms；整段音轨不截断视频尾部 | 初始速度调整范围 0.9-1.1 倍；超范围应调整译文/分段或提示，不能无限加速 |

CER/WER 使用编辑距离定义，报告替换、删除、插入及参考长度。数字和专名检查在规范化前单独完成，防止把错误数字规范化掉。无语音夹具不计算 CER/WER，按“不生成虚构转写”单独判定。

### 5.3 基线与用户价值

| 对照 | 使用方式 | 防止错误结论 |
| --- | --- | --- |
| 直接模型调用 | 对适用图片任务，以相同源图、蒙版、模型和预算直接提示作为基线 | 若 Agent 只是增加步骤却不改善局部控制/多轮修改/交付，不算已证明价值 |
| 人工编辑 | 至少 6 个代表任务，使用明确记录版本的现有工具人工完成 | 同时统计 Agent 等待、人工纠正与检查时间；不同人/工具熟练度写入报告 |
| 冻结前一版本 | 同一夹具、模型 profile、硬件和配置 | 新方案不能靠更高分辨率限制、更多费用或更强模型掩盖架构退步 |

初始用户价值目标：在达到同等质量的代表任务中，“实际操作 + 必需修正”的中位时间比人工基线减少至少 20%。总墙钟耗时单独报告；如果质量达标但价值目标未达到，只能列为实验能力并继续优化，不能直接标正式准入。

## 6. 性能、费用与资源

| 档案 | 测量条件 | 必须记录 |
| --- | --- | --- |
| CPU | Windows、无 GPU 加速、明确线程数 | CPU 型号、RAM、解析/导出耗时、进程树峰值内存；不承诺本地大生成模型可运行 |
| GPU | 明确 GPU/显存、驱动与推理版本 | 首次加载、暖运行、显存峰值、OOM 行为、队列等待 |
| Remote | 明确 Provider/模型与输入输出参数 | 网络等待、上传字节、实际 usage、任务/图片/音频计费单位与估价版本 |

每个正式 profile 必须在 G0/G4/G6 冻结具体最大素材规模、任务超时、进程内存/显存/磁盘上限和费用上限；缺少这些值时不能判该 profile 准入。本文输入规模是产品建议，不能替代机器实测。费用无计价依据时记录 unknown，不写成 0；真实调用前仍须有可执行的请求/生成次数上限。

| 指标编号 | 目标与测量方法 |
| --- | --- |
| PERF-01 | 本地点击/取消的可见反馈 P95 <= 100 ms，至少 30 次交互；不把模型返回耗时算为首次反馈 |
| PERF-02 | 重任务运行时使用 Qt 事件循环探针与后台 health 请求检查响应；与同机空闲基线比较，记录 P95 与最长停顿，出现 >= 1 秒 UI 停顿即失败 |
| PERF-03 | 本地可终止 worker 在取消后 5 秒内退出并释放文件句柄；远端在途调用单独记录，取消后新调用数必须为 0 |
| PERF-04 | 未启用媒体模块时无重模型下载/加载；冷启动耗时增加不超过 max(基线的 15%, 300 ms)，空闲内存增加不超过 50 MB |
| PERF-05 | 默认重任务并发 1，队列/磁盘/内存不超过冻结 profile；错误或取消后没有属于本次任务的残留进程 |
| PERF-06 | 导出阶段失败后恢复，已验证生成/转写步骤重复调用数为 0；只统计仍有效且文件存在的缓存 |

冷启动至少 5 次；工具暖运行建议 30 次。真实模型不得为凑样本无预算重复调用：样本少于 30 时报告原始样本数、中位数、最大值，不把少量请求的 P95 当稳定性能承诺。首次模型下载、加载、排队、推理、渲染和用户审阅分别计时。

## 7. 故障注入与原有功能回归

| 编号 | 注入场景 | 预期行为 |
| --- | --- | --- |
| FAIL-01 | Provider 401/400/429/5xx、连接失败、结构不符 | 分类处理；无权限/参数错误不盲重试；限流尊重 Retry-After 与预算；不泄露 Key |
| FAIL-02 | Provider 接收请求后断线 | 保存请求标识并对账；不可确认结果时停驻，不能自动重复消费 |
| FAIL-03 | 生成已完成，导出前应用退出 | 恢复已验证生成结果，继续导出；源或版本改变则明确失效 |
| FAIL-04 | 新 revision 已提交，旧 worker 迟到 | 旧结果不能覆盖当前工程，可标记为旧版本候选 |
| FAIL-05 | 磁盘满、输出路径不可写、文件仍被播放器占用 | 无假成功；保留已完成结果，释放可释放句柄并提供重试入口 |
| FAIL-06 | GPU OOM、依赖缺失、worker 非零退出 | 有准确原因和能力状态；不静默外发到云端，不使主应用退出 |
| FAIL-07 | TTS 失败但字幕完成 | 保留字幕并列明缺少配音，后续只重做失败部分 |
| FAIL-08 | 任务取消后 WebSocket 断开又重连 | 保持 cancelled，去重历史事件；不能恢复为 running 或自动重试 |

## 9. 运行步骤与证据包

1. 开发者确认阶段、代码版本、fixture hash、profile 和剩余预算，使用隔离数据目录，不读写用户生产库。
2. 先运行 E0/E1 与适用故障注入，修复后再进行真实模型检查；模型接口成功不提前更改能力状态。
3. 小样本真实探针验证连通性和输出类型；连通性测试不计入内容质量成绩。
4. 参数冻结后运行开发/留出质量测试；失败项与超时保留，记录每次 attempt 和费用。
5. 完成人工盲评、Qt 全流程与既有功能回归，依据 G 表逐项判定。
6. 整理证据，更新状态和下一阶段入口。实际用户操作说明在对应界面存在后补充，包括入口、材料、预期结果和是否计费。

建议证据输出至测试专用目录的 `media_evaluations/<run_id>/`，包含：

| 文件 | 必须包含 |
| --- | --- |
| `run_manifest.json` | run_id、commit、fixture/profile hash、机器/模型版本、预算、开始结束时间 |
| `cases.jsonl` | 每个 case 的输入引用、attempt、check 结果、错误和产物引用 |
| `metrics.json` | 原始分子分母、开发/留出分组、耗时样本、资源峰值、实际/未知费用 |
| `review.csv` | 人工匿名评分、分歧与复核结果，不包含真实个人身份信息 |
| `acceptance.md` | G 编号、required 清单、通过/失败/未运行项、证据索引、残余限制 |
| `artifacts/` | 可追溯测试产物、必要的截图/短录屏；未经许可不上传 GitHub |

以上是未来证据包规范，本轮没有创建虚构的成绩文件。

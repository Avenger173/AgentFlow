# 调度台可靠性、会话体验与模型控制整改计划

最后更新：2026-08-31
状态：**整改进行中：R0.1/R0.2/R0.3 已完成，R1 已完成受控材料导入与绑定，R2 已完成首轮阅读与布局修复，R3.1/R3.2/R3.3 已完成会话空间/中文链路、材料同步与首批工作台活动状态，R4.1/R4.2 已完成调度台及首批专业工作台模型入口，R5.1/R5.2/R5.3 已完成自然会话、材料续聊、任务意图优先路由与受控图表 Runtime，R5.4A/R5.4B/R5.4C 首版数据交付已完成；其余 R3/R4、R5.4C 扩展和 R5.4D 仍待实现。**

## 1. 目的与依据

本计划处理客户在真实使用中暴露的跨模块问题：文档列表超时、首次启动期间提交卡住、调度台对话内容拥挤且被输入框遮挡、Markdown 表格失真、会话列表 `404`、`@` 菜单中文乱码、材料无法从总指挥可靠地绑定、模型只能隐式或全局切换等。

它不是新 Agent 立项，也不重做已经完成的 C6.5.4。C6.5.4 的“单资料库安全问答自动交付最终结论”继续保留；本计划负责让它在真实桌面端更可靠、更像面向客户的聊天产品。

实施时必须同时遵守：

- `SKILL.md`：启动期暂存、会话记忆分层、显式模型路由、状态真实可见与 UTF-8 约束。
- `docs/COMMANDER_C6_PRODUCT_PLAN.md`：C6.2/C6.2.5 会话归档、C6.3 材料绑定、C6.4 专业委派、C6.5 路由 Profile 的既有事实。
- `docs/前端设计可借鉴文档.md`：渐进披露、底部命令栏、状态机、50-100ms 首次反馈、控件不依赖鼠标 Hover、错误状态可解释。

## 2. 已知事实与暂不下结论的事项

### 2.1 已确认的能力

- 后端已经存在会话列表、会话上下文和分页正文接口；会话正文会持久化，模型 Prompt 只读取有界摘要和最近消息。
- 后端已经存在文档、数据集和资料库的受控材料模型；C6.4 已具备有限的只读组合委派。
- 后端已经存在按任务作用域保存的 `Model Route Profile`，并且历史任务可审计实际 provider、模型和 thinking 快照。

### 2.2 必须先诊断、不能凭截图猜测的根因

- 文档助手的 `workspace` 文档列表为何 `Operation timed out`：需核对 Qt 请求超时、BackendManager 就绪状态、运行中的后端版本/端口以及文档列表 API 的实际耗时。
- 会话列表的 `HTTP 404 NotFound`：接口代码存在不代表运行中的后端一定是当前版本；需验证 Qt 拼出的 URL、后端路由注册、启动目录和旧进程占端口情况。
- `@` 菜单乱码：源码当前应按 UTF-8 处理，仍需沿着 Qt 菜单字符串、JSON 解码和 MSVC `/utf-8` 编译链复现定位，不能先假设是某一个文件编码问题。
- 删除 DeepSeek 官方控制台密钥后项目是否仍可调用：本轮不联网调用，也不读取或回显任何 Key。下轮只做本地“配置存在性/当前路由”检查；是否做小额度连接测试由客户主动点击确认。若当前保存的 Key 已被服务端撤销，真实调用应被准确显示为认证失败并引导重新配置。

## 3. 产品决策

### 3.1 调度台主区只负责对话，不展示内部控制台

对普通只读问答，客户应该看到：自己的问题、真实运行状态、清晰的最终答案、必要的来源和下一步。计划 DAG、节点契约、工具参数、事件流、Runtime ID、复盘指标和完整日志只能进入“查看计划”或历史任务 Inspector。

客户消息右对齐、使用与助手消息可区分的气泡和背景；助手消息左对齐、支持层级化 Markdown。输入框固定在对话工作区底部，但不覆盖可滚动的结果区域；内容区需为输入栏保留稳定底部空间。

### 3.2 项目范围降级为低频“会话空间”设置

当前“本次任务的项目范围”名称会让客户误以为它决定文件权限或本轮材料范围，实际它只是会话/长期记忆的隔离标识。因此：

- 默认不打断客户对话，使用全局会话空间。
- 将入口移入会话历史或低频会话设置，命名为“会话空间”，用一句话说明“将这段对话与可复用偏好隔离到一个项目下”。
- 材料选择、文件权限和 Agent 权限继续在各自位置说明，绝不借用“会话空间”概念。

### 3.3 总指挥导入不是“任何文件直接交给 LLM”

总指挥应支持客户从一个材料入口导入或选择已有材料，但仍需按真实能力分流：

| 文件类别 | 进入的受控材料 | 当前可委派能力 |
| --- | --- | --- |
| `txt` / `md` / `pdf` / `docx` | 文档材料或资料库材料 | 文档交付/审查、知识库检索 |
| `csv` / `xlsx` | 数据工作台数据集 | 画像、预览、只读数据分析 |
| 图片型 PDF / 图片 | 资料库 OCR 路径（已准备时） | OCR 后索引与知识库问答 |
| 不支持或不安全的类型 | 不导入 | 明确说明可支持格式与下一步 |

导入成功后，Qt 必须收到稳定的材料引用再写入本轮标签；不能只显示文件名或把本机绝对路径交给模型。数据集需要能从总指挥选中并绑定到 C6.4 的 `data_agent`，而不是要求客户重新进入数据工作台寻找文件。

### 3.4 会话历史是默认能力，不是临时任务列表

- 首次客户消息创建会话；会话标题先由本地确定性规则生成简短标题，例如截取清理后的首句，而不是显示 `task_llm_xxx`。
- 后续可以在明确有价值时使用一次受控模型重命名，但不为标题额外阻塞首轮对话或消耗客户额度。
- AI 调度台提供清晰的会话列表、当前会话标识、新建会话、切换和继续聊天；切换后恢复客户可读的历史，模型仍只取得摘要和最近轮次。
- 会话、任务历史和跨会话长期记忆继续分层：会话可自动连续，长期偏好必须可见、可编辑、可关闭、可删除。

### 3.5 模型选择采用“全局默认 + 作用域显式覆盖”

每个需要 LLM 的客户功能都能显示当前实际路由，并允许选择：

1. 继承全局默认；
2. 选择已经配置的 provider/model/thinking Route Profile；
3. 在有权限的模型设置页新建或编辑 Profile。

文档分析/PPT、数据洞察、知识库问答/深度分析、总指挥规划/汇总等作用域各自保存选择。功能页只显示紧凑的当前模型按钮或 Inspector，不把复杂 Provider 表单塞进每个工作台；运行记录必须保存实际路由快照，禁止隐式换模型。

### 3.6 “自动检测模型”必须有真实的兼容性边界

配置一个 API Key 不等于每个 Provider 都允许安全、完整地列出所有模型。模型页采用三层来源，并明确标记来源和刷新时间：

1. **内置目录**：已知 Provider 的稳定模型 ID、能力和默认值，不需要网络。
2. **Provider 枚举**：只有该 Provider 的正式接口和 Key 支持时，客户主动点击“检测可用模型”才请求；结果缓存且不保存 Key。
3. **手动模型**：兼容接口不支持枚举时，客户可填写模型 ID 并运行小额度连接测试。

thinking 开关由“Provider + 模型 + 当前传输协议”的能力判定控制，不能因为页面有一个开关就假称任何模型可用。检测失败不能覆盖用户已保存的配置，也不能自动切换到其他 Provider。

### 3.7 总指挥按任务意图编排，材料与 `@` 只提供受控线索

- 已选文档、数据集和资料库是本轮**候选上下文**，不是“下一句话必定读取它”的隐式命令。普通聊天不会因为上一步留下 CSV 就被改造成数据任务。
- `@文档助手`、`@数据工作台`、`@知识库` 只表达路由偏好；它们不能扩大材料范围、工具权限或已实现能力。制作 PPT 这类更明确的目标优先于残留材料或 `@` 标签。
- 总指挥以一份后端校验过的 action 目录决定真正可调用的 Tool。当前数据路径包括只读分析、“分析后生成 PNG 图表”和“分析后生成工作簿”；字段加工副本等需要结构化字段选择的能力不伪装成一句话即可安全完成。
- 无副作用的单材料问答/分析自动执行；会写入受控产物的计划在聊天中说明范围，并由客户回复“开始执行”进入 Runtime。真实权限策略仍由 Runtime 二次裁决，不能把一句聊天文本当成绕过批准的凭证。

## 4. 分阶段实施

### R0：运行版本、启动和导入诊断（P0）

**目标**：先让“当前 Qt 连接的是哪个后端、后端是否 ready、请求为何超时/404”可观测，再修复现象。

- 在不含正文、路径和凭据的前提下记录客户端请求 URL、HTTP 状态、请求阶段和耗时；区分“后端尚未 ready”“API 不存在”“请求超时”“材料不存在”。
- 复核 `BackendManager` 的启动、端口占用和版本探测，避免 Qt 连到旧后端进程。
- 文档列表、会话列表和材料导入都改为显式状态机：`未开始 -> 暂存/加载 -> 成功 | 可重试失败`，请求去重、超时后保留客户输入和材料选择。
- 页面初始化由显式启动信号、定时就绪检查或真实 API 回调驱动；不得依赖鼠标移动、重绘偶然触发或客户反复点击。
- 只在后端 ready 后提交实际导入/聊天任务；启动阶段先在 50-100ms 内给出“已暂存，正在准备后端”。

**验收**：冷启动、后端旧进程占端口、后端未 ready、文档列表慢响应、会话列表 API 不存在五种夹具都能得到不同且可操作的客户提示；没有输入丢失或无限转圈。

#### R0.1 文档列表性能与会话 URL 修复（已完成，2026-08-27）

- 已定位并修复会话列表/正文的 Qt URL 构造错误：原实现把 `?project_scope=...` 放入 `QUrl::setPath()`，请求会被编码为不存在的路径，造成客户看到 `HTTP 404 NotFound`。现在使用 `QUrlQuery` 单独构造 query，保留项目范围、分页和 UTF-8 参数边界。
- 已定位并修复 workspace 列表性能边界：原列表会逐份调用完整 PDF/DOCX/图片解析，扫描件甚至可能进入 OCR。现在列表只读取文件名、类型、大小和修改时间；文本短预览只在导入成功的即时反馈中读取，二进制材料解析仍按需由 preview API 或 Agent Tool 执行。
- 已新增 `backend/scripts/verify_workspace_document_listing.py`，在把完整解析器替换为失败夹具后验证列表仍能返回 TXT/PDF 元数据；`verify_commander_c6_conversation.py`、`verify_backend.py`、`compileall`、`pip check` 与 Qt Debug 构建均已通过。没有运行真实模型、OCR 或客户材料。
- R0.3 已完成启动失败、端口复用与显式重试的首轮客户可见诊断。后续只根据可稳定复现的启动故障补回归，不把所有请求失败误归因于后端启动。

#### R0.2 workspace 清单并发收敛（已完成，2026-08-27）

- 启动完成、首次进入文档页、PDF 工作区与文档导入完成都可能请求同一份 workspace 清单。`BackendClient` 现在以单个飞行标记合并并发只读 GET，成功或失败时先释放标记，再向各页面广播同一结果；因此导入完成的下一次刷新不会被旧慢请求覆盖，也不会在失败后锁死为“加载中”。
- 这不是内容缓存，不改变 6 秒客户可感知超时，也不延后客户主动刷新；它只消除同一进程内没有额外价值的重复请求。后端清单仍只读取文件元数据，不解析 PDF/DOCX/OCR。
- Qt Debug 构建、`verify_workspace_document_listing.py` 与 `verify_backend.py` 已通过，未读取客户文件、未调用模型或网络。

#### R0.3 后端启动故障、端口复用与显式重试（已完成，2026-08-27）

- `BackendManager` 的健康检查现在采用单飞行保护。客户点击顶部状态条的“重试后端”时，会取消迟到的旧探测；若 AgentFlow 自己启动的后端仍在运行，只重新探测，不会无故停止或重启它；否则回到既有的“先探测、后启动”链路。
- `127.0.0.1:8765` 若已有服务但 `/health` 没有返回合法的 AgentFlow 就绪状态，客户端会明确提示端口被非 AgentFlow 服务占用，并要求关闭占用服务后重试；不会在同一端口再启动第二个 Uvicorn。进程错误、超时和网络竞态会收敛为同一条最终客户提示，并附启动检查耗时。
- “重试后端”只会在后端未就绪时显示；后端就绪后自动隐藏。启动期提交仍保持既有的排队/保留输入语义，本轮没有把材料解析、模型调用或专业 Agent 初始化加入启动路径。
- 新增 `BackendManagerTests` 回环测试，覆盖合法 AgentFlow 健康响应、非 AgentFlow HTTP 响应拒绝以及显式重试不拉起第二个进程；CMake 已为 Windows CTest 配置 Qt 运行时路径。Qt Debug 构建、`BackendManagerTests`、`verify_backend.py`、`verify_commander_c6_conversation.py`、`compileall` 与 `pip check` 已通过，未调用真实模型、Provider API 或客户材料。

### R1：材料导入与 Commander 绑定闭环（P0）

**目标**：文档、数据和资料库从各自页面或总指挥带入时，都能可靠获得可审计的受控引用。

- 修复文档助手的工作区材料列表加载与失败重试；页面不可因为单次列表失败永久禁用全部任务。
- 建立总指挥统一材料选择器：显示类别、状态、来源页面、可调用 Agent 与受限格式；导入后异步刷新并自动绑定稳定 ID。
- 补齐 CSV/XLSX 进入数据工作台、在总指挥选取已有数据集、委派 `data_agent` 的回归；未知类型不假装已导入。
- 材料标签展示“已绑定/索引中/不可用/需要重试”等真实状态，移除标签不删除源文件。

**验收**：从调度台导入或选择一个 CSV/XLSX 后，`@数据工作台` 能生成并执行允许的只读数据任务；文档列表故障时可重试且不挡住已有材料；客户不会看到绝对路径或内部 ID。

#### R1.1 调度台 CSV/XLSX 导入直达（已完成，2026-08-27）

- 调度台附件入口已按受控材料类别分流：`csv/xlsx` 进入既有数据集导入 API，不再伪装成工作区文档；导入成功后只绑定后端确认的相对引用，自动显示为本次材料，并保留 `@数据工作台` 的只读分析边界。
- 后端尚未 ready 或同一份数据仍在导入时，客户端会保留客户选择并给出可重试状态，不会提前发出必然超时的 HTTP 请求；从数据工作台发起的原有导入流程保持不变。
- 已复跑 `verify_data_workspace.py`、`verify_commander_c64_runtime.py`、`verify_backend.py` 及 Qt Debug 构建；没有读取客户数据、没有调用模型或联网。

#### R1.2 调度台统一“选择已有材料”（已完成，2026-08-27）

- Composer 的“添加材料”改为两个明确动作：从电脑导入，或选择已经受控导入的材料。后者使用独立的轻量对话框，允许本次任务同时绑定一份文档、一个资料库和一份 CSV/XLSX 数据集，不把三个长期下拉框塞进主对话区。
- 选择器只同步文档、资料库和数据集的目录元数据（名称、类型、大小、索引状态）；不会触发 PDF/DOCX/OCR 解析、知识库索引、CSV 画像或模型调用。只有客户发送任务后，后端才按既有 C6.4 action 准入实际校验并委派对应专业能力。
- 客户点击“应用材料”后，Qt 仅保存后端确认的相对材料引用；材料标签仍可单独移除，发送后仍按既有规则清空本轮只读范围。目录同步中、后端准备中和单类目录失败会显示可理解状态，并可主动重新同步。
- 工作区目录请求继续沿用 R0.2 的单飞行收敛；数据/资料库目录同步不会顺带加载整表画像或知识库正文。Qt Debug 构建、UI XML/UTF-8 检查、`verify_workspace_document_listing.py`、`verify_commander_c64_runtime.py` 与 `pip check` 已通过，未读取客户材料或调用真实模型。
- R1 的受控导入、已有材料绑定、稳定引用和 C6.4 只读委派路径现已完成。本阶段后续只在真实客户复现发现的导入/状态问题上修复，不再为材料入口增加新的独立流程。

### R2：调度台阅读与会话体验（P0）

**目标**：聊天内容在常见分辨率、缩放比例和长结果下都可读、可继续、不会被输入框遮挡。

- 调整 `.ui` 布局：对话滚动区、状态区、材料标签区、底部输入 Composer 使用稳定的纵向布局约束；窗口缩放和高 DPI 下不重叠。
- 为用户/助手消息建立统一气泡组件风格：宽度约束、右/左对齐、清晰的背景与边界、简洁状态指示；不要把每条日志写入消息流。
- 扩展受限 Markdown 渲染器：标题、段落、列表、加粗、行内代码、引用和 GitHub 风格表格。表格需解析对齐分隔行、转义单元格、统一列数；无法安全解析时降级为等宽文本，绝不拼接未转义 HTML。
- 把“查看计划/任务详情”保留为独立 Inspector；主对话只显示计划一句话、执行状态和最终交付。
- 修复会话列表 `404`：先用 R0 确定运行版本与 URL，再补齐客户端 API 调用、后端路由回归和错误恢复。会话菜单显示自动标题、更新时间、当前标记，而不是技术任务 ID。

### R5：自然会话、材料路由与安全自动执行（P0）

**目标**：让 AI 调度台先像正常的聊天产品一样工作。普通问题直接得到真实回答；客户明确绑定的一份只读材料可以自动完成受控分析；计划、日志和历史审计仍可追溯，但不占据聊天主视图。

- 数据工作台交接时，客户端可写入可见的 `@数据工作台` 路由偏好，但后端必须仍以客户目标、受控数据集 ID 和 action 准入为最终依据；标签不能过滤其它已选材料，更不能强制本轮读取 CSV。
- `direct_answer` 是普通对话，不得被客户端替换成“已生成可执行方案”、任务拆解或 dry-run 文案。模型只收到有界会话上下文与客户问题，并应直接给出清晰、分层的回答。
- 自动 Runtime 只对白名单内的单材料、只读、无联网、无写入、无需确认的任务开放：已索引资料库问答与已绑定数据集分析。白名单外的多 Agent 编排、深度分析、导出/写入、联网、命令或任何需确认步骤，仍必须由客户明确确认后执行。
- 自动只读任务从 dry-run 进入 Runtime 后，调度台显示简短运行态；完成后把经子 Agent 输出契约约束的结论追加到同一会话。原数据、原始行、内部日志、计划细节、权限审计和完整产物留在对应工作台或任务历史，不混入聊天回答。
- 任何自动化规则均以已校验的 WorkflowPlan 为前提；客户端不得仅根据关键词自动点击执行，后端不得因 `@` 标签扩大材料范围、权限或模型工具能力。

**验收**：从数据工作台交接一份数据后，“分析当前数据文件”会路由至数据工作台并直接交付趋势、差异与图表建议；明确“制作/导出图表”会形成可见的写入计划；普通常识/创作问题显示真实模型回答而不是计划；安全白名单外任务仍保留确认入口；会话恢复后能读到追加的专业结论，且不泄露原始数据或审计细节。

**R5.4B：字段加工的结构化自然语言计划（P0，已完成 2026-08-31）**

**R5.4C：多数据集交付（P1，首版已完成 2026-08-31）**

- 首版只接受客户明确绑定的两份 CSV/XLSX；当两份数据只有一个同名字段时自动采用该字段，存在多个候选或没有明确关联键时转为澄清，不把模型猜测当成连接计划。
- 首版支持 `left` 和 `inner` 连接，重复非空键直接拒绝，类型不兼容或源哈希变化时只返回可读错误；预览阶段只返回行数、匹配数、字段冲突和有限样例，不写文件。
- 客户确认后在 `output/data_joins/` 生成新的同类型副本，CSV 使用 UTF-8 BOM，XLSX 使用无样式单表；回读列、行和两份源版本后才登记子任务 artifact，并把文件名、统计和源文件未修改写回当前会话。
- 2 至 4 份数据、复杂关系、重复键聚合、字段映射和任意 SQL 仍未开放，后续必须另行设计、验证和审批，不能把首版宣传成通用多表引擎。

**R5.4D：通用会话结果卡（P1）**

- 建立统一的 `agentflow.delivery.v1` 持久化和 Qt 渲染适配层，先接数据、知识库和文档，再接后续 Agent。卡片以“结论优先、事实可扫读、产物可打开、下一步可继续”为顺序；图片类 artifact 显示缩略预览，表格类只显示有限摘要，长报告默认折叠。
- 客户看不到内部 task ID、绝对路径、原始行、完整日志或模型思考过程；点击“查看过程/查看历史”才进入审计面。重复状态刷新、Runtime 恢复和会话重载必须按稳定交付 ID 幂等，不重复添加结果卡。

**验收**：用户在调度台绑定 CSV/XLSX 后，能依次说“分析当前数据”“生成图表”“开始执行”，在同一会话看到已验证图表和打开入口；说“生成分析 Excel”“开始执行”得到新工作簿；说“根据金额、数量和日期新增金额排名、累计金额、月份字段”得到受控预览，确认后在同一会话获得新副本。任一步失败都会保留原文件、说明失败阶段和可重试建议；模型不能借自然语言输出任意表达式或跨数据集猜测关联。

## 5. 回归与性能约束

- 先补 R0 的脱敏诊断夹具，再写 UI；每个 HTTP `404`、`timeout`、未 ready 和旧进程场景都需在离线测试固定复现。
- Qt 侧使用真实事件循环/信号回调验证初始化，不只调用槽函数；重点覆盖首次启动、最小化/恢复、窗口缩放、慢响应和重复点击。
- Markdown 表格用固定中文/英文/空单元格/不规则列数用例测试；渲染层不得解析远程 HTML、脚本或原始富文本。
- 模型发现默认不联网；真实 Provider 检测与连接测试必须显式触发，输出只记录 provider、model、能力、HTTP 类别和耗时。
- 每一阶段完成后更新本计划、`PROJECT_STATUS.md` 与对应既有 C6 文档；不在未验收时把计划写成“已完成”。

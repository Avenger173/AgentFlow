# PPT 智能研究与数据设计

最后更新：2026-08-14

本文约束 PPT 制作 V3 的第三步“智能数据规划、数据生成与图表”。它属于文档助手的内部
Data Harness，不新增面向客户的小 Agent，也不要求为每个领域持续增加专用 MCP。

## 产品目标

客户只需说明“想做什么 PPT”。系统自动判断是否需要数据、需要比较什么、使用何种时间和
统计口径、适合什么表格或图表，并在客户确认导出后由已配置模型直接生成数据底稿。最终交付必须包含
可编辑图表或表格、有限的数据合同和任务审计；普通创作不联网、不等待来源验证。客户明确选择
“联网核验”时才进入公开资料检索与证据流程。无论哪种模式，都不能静默交付零图表，且不能把未核验
数字表述为已核验事实。

## 当前默认执行链

1. **规划**：主创作模型负责内容和版式；专用数据规划器负责对象、指标、逐页图表类型、数量合同和数据点预算。客户原句中能稳定识别出的单对象或对象对是不可越界的对象合同，模型不得擅自补入高频关联对象。主模型无法稳定输出 JSON 时，可以受控切换一次已配置后备模型，不更改用户默认设置。
2. **数据直出**：客户确认导出后，数据模型按已固化蓝图直接生成至多 36 个数据点。它不得扩大对象或指标范围，也不得创建 URL 或声称已联网。只要 JSON、受控标签、有限数值与图表形态成立，即写入可编辑原生 Table/Chart。
3. **合同优先**：客户点明“4 张图表、表格、折线、饼图、柱图”时，类型和总数都是硬合同；简短“生涯数据”才由规划器补齐互补视图。单对象的展示型饼/环图或横向指标画像可使用 AI 草稿中的多项指标，并逐项展示单位；联网核验模式仍保留同单位、同期间的严格要求，不能因此静默少交付一张图。
4. **可选联网**：只有客户明确选择“联网核验”时，固定 Provider、ResearchGateway 或受控 MCP 才可读取外部资料；此时来源、单位、期间和证据片段的严格审查重新生效。
5. **真实回归**：修改模型规划、数据直出、图表渲染或图像 Provider 后，在用户授权额度下运行 `backend/scripts/verify_live_presentation_studio.py --live`；只记录脱敏的 provider、视图、数据点和图片数量。

## 可选联网核验链（非默认）

1. **职责隔离的规划**：主创作 LLM 只输出 PPT 简报、逐页内容和版式；Harness 先从客户自然语言
   提取“至少 N 张表/图”的数量合同，重复要求取最大值而不是相加。随后再调用一次无工具、零联网的
   专用研究规划器。简短输入由它主动扩展为 3 至 5 个互补视图；详细输入优先遵从客户类型与数量。
   它规划对象、最多 6 个横向指标、独立趋势指标、逐视图指标组、检索别名、时间范围、
   比较口径、目标页面、所需数据点、3 至 6 条查询语句与来源
   偏好，不输出事实数值。研究蓝图先兼容常见字段别名、嵌套对象和整数文本；仍不合格时最多做
   一次同样零联网、无工具的 JSON 修复。仅当客户明确点出两个对比对象，且原始主题或页面计划
   已出现可量化指标时，才允许建立不含任何数值、URL 或来源的保守查询蓝图；其余模糊主题必须
   提示补充，不能为了有图表而猜对象或指标。研究规划失败不能拖垮已合法的主创作计划。
2. **数据路由**：优先选择已经验证的结构化快捷 Provider，例如 World Bank；没有匹配的固定
   Provider 时，再交给统一 ResearchGateway。MCP 只作为 ResearchGateway 的可插拔工具来源，
   不是 PPT 功能工作的前提。
3. **受控联网**：只有计划已固化、客户确认本次联网后才能执行。首轮优先共同查询与各对象聚焦
   查询并发聚合，默认最多 6 条查询、一次补查；多指标或多图任务会一次消费完整的已确认查询
   蓝图并复用来源，不为每张图重复联网。每个来源和整项任务都设置超时。
4. **结构化抽取**：抽取 LLM 只能依据搜索工具返回的受限内容抽取对象、指标、数值、单位、
   时间、统计口径和来源 ID，不得凭模型记忆补数，也不得自由创建 URL。若当前默认 Kimi 对
   公开网页片段触发内容过滤，而本机已配置 DeepSeek，Harness 会在不修改全局默认配置的前提下
   直接使用 DeepSeek 非思考模式承担这一步；内部路由使用正式任务预算，不能复用连接测试的
   64-token 预算。
5. **分级验证**：Verifier 逐点检查数值、来源 ID、原文片段、对象和单位。数据满足同来源/同期间时
   可画比较图；来源或期间不同但每个对象都有证据时，改为逐项标注来源和期间的演示对比表，
   不以审计级条件整表否决。单个点引用无效时只丢弃该点并记录数量；剩余点仍须重新满足完整
   对象/指标/图表口径。模型翻译或改写引用时，只允许通过对象、数值、指标别名和期间在其指定
   来源中恢复真实连续原文，找不到仍拒绝。
6. **AI 草稿补齐**：公开来源已经通过 Verifier 的视图始终优先。缺失页面可再由一次无工具模型调用
   按已确认实体、指标和视图返回至多 36 个数据点；本地仍校验有限数值、对象、指标、单位和图表形态。
   这类视图统一标为 `ai_knowledge_draft`，页面显示“未经公开来源逐项核验”，来源页和 artifact 同步记录。
7. **交付与审计**：一次研究结果可按客户要求拆成至多八个独立数据视图，并分别放到不同正文页。
   多张横向表按不同指标组拆分，趋势明细表与折线图复用同一组逐期数据，不能复制同一表格凑数。
   首轮只满足部分视图时，第二次抽取会复用
   同一批来源专门补缺失视图，不新增搜索；失败只跳过该视图，不撤回其它结果。表格使用 PowerPoint
   原生 Table，柱图、横向条形、折线、面积、饼图和环形图使用原生 Chart；回读直接核对 Chart 内嵌系列值。来源页去重记录证据，
   artifact 保留每个实际落盘视图的完整审计元数据，并记录数量合同是否完整、各类型实际数量和缺口。

## 用户可见的阶段语义

- **生成计划**：主创作模型先生成简报、页面与视觉计划；若客户启用智能数据，再由专用研究
  规划器生成对象、指标、口径和查询蓝图。两次模型调用都不联网、不读取数据、不生成数值，
  因此“计划阶段尚未联网”是正常的权限边界，不代表模型 Key 未配置或调用失败。
- **研究蓝图恢复**：供应商把 `entities` 写成 `subjects`、把整数写成“第 2 页”这类格式差异，
  会在本地规范化；首次 JSON 不完整会显示一次结构修复。恢复后的 `research_planned` 只表示
  “导出时应进入 ResearchGateway”，不表示已经得到事实或数据。任务历史会记录研究规划器实际
  调用 1 次或 2 次，方便客户复盘而不把格式恢复误解为联网取数。
- **确认导出**：客户确认本次联网后，ResearchGateway 才执行受控搜索、读取公开证据，然后由
  第三次模型只从这些证据片段抽取数据，最后交给 Verifier。搜索、读取、抽取、补查、验证、
  渲染和回读阶段会同时写入实时事件和 SQLite 任务历史。
- **实用降级**：不能证明共同口径时先从比较图降为带来源表格；仍缺失的视图可补成 AI 数据草稿。
  草稿是可编辑创作底稿，不是权威核验结果；模型也无法形成合法数据时才报告部分完成并列出缺口。
- **网页读取快照**：来源给出当前数值但未写统计截止日时，系统可把该点期间标为“网页读取快照
  （抓取日期）”。同页同单位可画比较图；不同来源或混合明确年份时只能做逐项标注的表格，不能把
  快照说成官方统计截止日。

## 图表选择规则

- 多对象、单一指标、同一时间：对比表或柱状图。
- 单对象或多对象、同一指标、每个对象至少三个共同时间点：单序列或多序列折线图。
- 多对象、多个同量纲指标：分组柱状图或数据表；数据密度过高时优先表格。
- 标签较长、需要排名或单对象同量纲指标画像：横向条形图。
- 连续时间序列需要强调累计变化或规模：面积图；普通趋势仍优先折线图。
- 同一整体的非负组成项：饼图或环形图；不是构成关系时禁止使用。
- 雷达图只有在指标已经可靠归一化且量纲可比较时才允许使用。
- 单位一致但来源、时间或统计口径不一致时，不生成比较图，改为逐项标注的对比表；不能把“各自
  最新值”伪装为同年比较，也不能把有证据的数值静默丢弃。
- 主创作计划中的数字不是数据证据。客户未提供且尚未通过 ResearchGateway/固定 Provider 验证的数字
  必须在计划落库前移除；渲染后的 PPT 还必须回读每个数据表/图表数值，避免交付文件出现空单元格。

## Provider 与 MCP 边界

- 固定 Provider 是高可信快捷通道，不代表所有主题都要增加专用代码。
- ResearchGateway 提供统一的搜索、抓取、来源标准化和预算接口；模型供应商的原生 Web Search、
  独立搜索 API、白名单 MCP Server 都只作为该接口的 adapter。当前已接入 Tavily Search adapter：
  它只返回 HTTPS 来源 URL 与服务端清洗的正文片段，搜索服务的自然语言 `answer` 和普通摘要都
  不可作为数值证据。
- 稳定搜索服务优先解决“本机逐页回读动态网站不稳定”的问题。Tavily Advanced Search 的 `content`
  是按查询重排的来源原文 chunks，可置于受限 `raw_content` 前进入证据上下文；供应商生成的
  `answer` 仍禁止使用。每个数据点必须命中保存的原文证据，缺少服务端正文时才受控直连回读。
- 网络策略默认遵循进程环境；Windows 浏览器代理不一定被 Python 网络库继承。客户可在本地 `.env`
  显式设置 `AGENTFLOW_PRESENTATION_RESEARCH_PROXY_URL`，或明确设置 `direct`；系统不读取注册表
  猜测代理地址，也不在任务、artifact 或接口中回显代理 URL。
- 第三方 MCP 的工具描述和返回均视为不可信输入。启用前必须登记来源、权限、网络域名、密钥、
  超时、价格与许可证；运行时按 Tool 白名单、用户确认和审计执行。
- 不允许模型自行安装 MCP、连接任意 MCP URL、把密钥写进 URL，或绕过平台权限模式。

## 第三步验收门槛

- “梅西与 C 罗的数据对比 PPT”能在计划阶段生成对象、候选指标、比较口径、图表类型和查询语句，
  而不是因不在静态国家表中直接判为无数据或因 JSON 格式差异退化为普通 PPT。
- 计划阶段保持零联网，修改研究蓝图相关选项后旧 `plan_id` 失效。
- 确认联网后至少完成一次通用主题的真实搜索、结构化抽取、来源验证与图表/表格交付。已于
  2026-08-13 在隔离真实环境完成；后续继续覆盖不同主题、来源质量和网络波动。
- 离线回归覆盖恶意 URL、无来源数值、单位冲突、时间冲突、缺失对象、重复补查和超时降级。
- Qt 已展示真实阶段：规划、检索、提取、验证、补查或降级；后续仍需以真实长耗时导出做可视验收，
  不能用假进度或最终才一次性返回。
- 用户明确要求多种数据、多个表格、柱状图和折线图时，计划必须保存逐类数量合同、2 至 6 个候选
  横向指标、独立趋势指标以及多期查询；
  若公开证据只支持部分视图，回执必须逐项说明，不得静默交付零张图，也不得把所有内容压成单行表。

# 数据工作台产品规格

最后更新：2026-08-18  
状态：**D5.1-D5.3 已完成工程 MVP；第三轮反馈修正已通过离线回归与 Qt 构建，等待真实 CSV/XLSX 的 Qt 本机复验。**

本文定义数据工作台从 D1-D4 工程底座进入客户可用产品时的范围。它补充
`AGENT_SPECIFICATIONS.md` 中“003 数据分析与表格交付 Agent”的技术边界；原有的文件安全、
确定性计算、产物回读、任务历史和权限约束继续生效。本文不是“功能已实现”清单，也不授权把
所有路线同时开工。

## 1. 产品定位

数据工作台面向不会公式、透视表、BI 或编程的客户，把一份真实 CSV/XLSX 转换为：

- 看得懂的结构、质量和可回答问题；
- 客户确认后生成的真实图表与可保存 PNG；
- 可复核、不会改动原文件的数据副本与派生字段；
- 可回到任务历史查看的计算范围、产物和失败原因。

它不是泛用聊天窗口，也不是让模型随意运行 Python/SQL 的表格编辑器。核心承诺为：**模型帮助
客户确定“可以做什么”和“怎样表达”，本地确定性工具负责真实计算、图表数据和文件交付。**

### 1.1 目标客户与真实任务

| 客户 | 常见材料 | 真实困难 | 数据工作台交付 |
| --- | --- | --- | --- |
| 办公/运营人员 | 销售、库存、订单、费用、项目台账 | 不知道第一步看什么，月报图表重复做 | 关键变化、可确认图表、Excel 副本 |
| 学生/研究助理 | 问卷、实验记录、成绩、观察数据 | 字段乱、图表选择困难、需要放进作业或报告 | 质量提示、分布/对比图、PNG 和数据范围 |
| 小团队负责人 | 周报/部门导出表 | 想快速判断异常、结构变化和重点项 | 可复用的分析视图与可追溯结论 |

不承诺因果关系、预测、投资建议、医学/法律结论或专业统计显著性检验。相关性、异常和趋势只能
表述为“数据中的模式/提示”，不能被包装成业务结论。

### 1.2 市场校准与产品取舍

主流表格 AI 已能根据自然语言分析数据、推荐或创建图表、生成透视表，并在某些产品中直接修改
工作簿。AgentFlow 不应把“上传 CSV 后给一段总结”或“画一张柱图”当作独有卖点。

本产品选择的差异是：单文件本地优先、源文件只读、每个图/字段都有可见计算合同、写入永远是
新副本、结果能成为任务历史 artifact。客户不需要懂得如何写提示词，也不需要相信模型计算了
正确数字才敢保存。

参考校准：

- [Microsoft Copilot in Excel 数据洞察](https://support.microsoft.com/en-us/office/identify-insights-with-copilot-in-excel-52d97339-86c0-431c-b46c-e7b07b2898dd)
- [OpenAI 数据分析说明](https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt/)

## 2. 共用产品原则

1. **先建议，后执行。** 客户上传后先看到数据能回答的问题和预计产物；不强迫写复杂目标。
2. **计算不交给模型。** 模型不能臆造数值、列名、公式、图表数据或文件路径。
3. **一个动作一个可见结果。** 每张图、每个派生字段都能查看数据范围、计算方式和影响行数。
4. **默认不外发原始数据。** 常规模型调用只接收脱敏字段画像、已计算指标和有限聚合表。
5. **源文件永不修改。** 图表、Excel 副本和未来派生材料都写入固定输出目录，默认不覆盖同名文件。
6. **问题可以不专业。** 用户可写一句自然语言；动态示例和推荐卡应比“提示词教程”更先出现。
7. **结果优先于过程，过程可追溯。** 主界面只展示当前任务和成果；复杂计划、数据范围、日志和
   artifact 在详情页或任务历史按需展开。

**D2 结论质量约束（2026-08-18）：**自然语言目标用于指定要解释的问题，不是把原始数据交给聊天模型。
确定性执行后必须先生成带表/指标 ID 的事实底稿：时间首尾、峰值/低谷、类别排名与差异、构成范围、连续
测量变化和质量影响。模型只能在该底稿上组织结论；当趋势与横向对比均存在时，结果至少覆盖两种视角。禁止
用“已生成 N 张图/表”充当结论，禁止无数值事实时杜撰数字，也禁止由相关或趋势推断业务因果。模型不合格时
使用同一份底稿生成本地结论，客户仍应直接看到具体发现与可执行的下钻建议。

## 3. 数据、模型与权限边界

### 3.1 数据可见范围分级

| 等级 | 可见数据 | 用途 | 默认状态 |
| --- | --- | --- | --- |
| L0 本地解析 | 完整受控文件，仅后端确定性 Tool 可读 | 画像、计算、渲染、回读 | 始终本地 |
| L1 规划上下文 | 字段名、类型、行列数、空值/唯一值/日期数值范围 | 推荐问题、选择图表或字段操作 | 默认允许 |
| L2 已验证结果 | 指标、有限聚合表、图表合同、质量统计 | 写简短结论、解释图表 | 默认允许 |
| L3 受控原始片段 | 客户明确选择的列、行范围和 Provider | 后续深度语义分析 | **未来能力，须单独确认** |

L3 不是本规格的 MVP。未来启用时，界面必须在执行前显示 Provider、模型、字段、行数、预计外发
范围和“不会修改源文件”的说明；未确认不得发送任何原始单元格给模型。

### 3.2 统一执行链

```text
导入文件
-> 本地画像与质量检查
-> 推荐问题 / 用户意图
-> 结构化计划（模型可选，严格 schema）
-> 白名单验证
-> 本地确定性计算
-> 图表或派生副本预览
-> 用户确认写入
-> 回读验证、artifact、任务历史
```

模型失败时必须降级为本地模板推荐与已验证结果，不撤回已完成画像或计算。模型 Provider 始终经
`ModelGateway` 选择；任何具体供应商、API Key、绝对路径、原始文件对象和数据库对象都不能进入
模型上下文。

## 4. 输入引导与轻量说明书

### 4.1 用户输入

主输入只保留“你想了解或做成什么？”这一句，可为空。客户不需要知道列名、聚合、图表类型或
公式语法。系统根据当前画像生成 3 至 5 个可点击的示例，例如：

- 有日期和数值：`看看每月金额趋势`、`找出波动最大的月份`；
- 有类别和数值：`比较各地区的金额`、`生成前十名排行榜`；
- 有问卷/评分：`比较不同分组的满意度`、`看看分数分布`；
- 有明显可乘数值列：`计算金额 = 单价 × 数量`；
- 无明确数据形态：`先检查缺失、重复和异常格式`。

客户的详细要求优先形成硬合同。例如“生成两张柱图和一张折线图”必须在计划中保留数量和类型；
简短要求则由推荐器主动补齐合理的有限视图。若无法唯一确定某个字段，最多询问一个真正影响结果
的问题，而不是抛出字段名或内部错误。

### 4.2 帮助入口

数据工作台右上角提供一个带 Tooltip 的 `?` 图标按钮，打开独立、聚焦的简短帮助窗口：

1. 导入 CSV 或 Excel，先看文件是否已准备好；
2. 点击推荐问题，或用一句话说明目标；
3. 预览图表/字段变更，确认后保存 PNG 或新 Excel 副本。

抽屉只显示当前数据可用的例子和明确限制，例如“当前没有日期列，不能生成趋势图”。它不是长篇
说明书，也不遮挡正在阅读的结果。

## 5. 路径 A：数据发现与可回答问题

### 5.1 客户价值

解决“我拿到一张表，但不知道先看什么”。它将当前数据的字段、时间、类别、数值和质量问题转换
成有限、可执行的候选方向，而不是空泛地说“可以进一步分析”。候选方向是后台辅助能力，不应
在主工作台用一大片固定卡片替代用户自己的目标输入。

### 5.2 输入、输出与界面

- 输入：当前已画像文件、可选一句目标、L1 结构画像。
- 后端输出：最多 4 条结构化候选，包含问题、所用字段、推荐理由和预计图表或表格。
- 默认工作台：不把候选固定渲染成主页面卡片。页面提供可见的 `? 使用说明`、按需展开的“字段详情”、
  与当前数据匹配的输入示例，以及底部的一句自然语言目标行动区。
- 辅助入口：候选可供后续 Inspector、命令面板或自动填充示例使用；只有客户主动选择某个候选时才进入
  统一分析链，不要求客户先阅读候选卡才能完成任务。
- 失败：没有可分析数值/日期/类别组合或候选请求超时时，不在主页面展示空白/报错建议卡；保留直接输入
  目标、查看字段和执行质量检查的路径。

### 5.3 结构化推荐合同

推荐器只可返回：`question`、`route`、`source_columns`、`aggregation`、`chart_candidate`、`rationale`
和 `expected_output`。`route` 限定为 `quality`、`comparison`、`trend`、`composition`、`distribution`
或 `transform_candidate`。Validator 必须确认列存在、类型适用、日期/数值数量足够、图表类型可渲染。

离线或模型失败时，以确定性规则输出同等数量以内的基础候选，供辅助入口使用。推荐本身不创建
task artifact；客户直接输入目标或主动选择候选后才进入统一任务链。

**D5.1 当前实现（2026-08-17）：**本地推荐器已按上述合同生成至多四条可执行候选，并由
`POST /api/agents/data_agent/recommendations` 提供。真实模型配置可用时，仅接收 L1 的字段名、
类型、行列规模、缺失/唯一值计数和本地候选卡，用于重排既有 `recommendation_id` 与润色一句引导语。
模型不能新增字段、数值、图表或操作；无 Key、超时、HTTP 错误、非 JSON 或无效候选都会直接回退
`local_fallback`。当前 Qt 默认页面不自动展示这些候选，避免“暂无法整理建议”这类后台状态挤占主任务
空间；L2 结果解释留给用户实际运行 D2 后的结果详情，不在推荐阶段伪造结论。

### 5.4 验收

- 只含日期、类别、数值和质量问题的合成表，能得到有据可查、彼此不重复的建议；
- 只有文本列的文件不伪造趋势/金额图，仍能得到质量与类别分布建议；
- 每项建议引用的列在数据画像中存在，点击后能转为可验证执行计划；
- 模型不可用时仍有本地推荐，客户不面对空白或“AI 失败”。

## 6. 路径 B：图表看板与 PNG 交付

### 6.1 客户价值

解决“我知道要看数据，但不会选择图表，也无法直接把图交给同事、老师或放进报告”。图表不是模型
生成的装饰图，而是由验证后的聚合数据渲染出的可读视觉资产。

### 6.2 图表合同与适用规则

初版允许的图表类型与条件：

| 图表 | 适用条件 | 典型问题 |
| --- | --- | --- |
| 折线/面积 | 有序日期或连续序列 + 数值 | 月度趋势、变化速度 |
| 柱图/横向条形 | 类别 + 数值 | 区域对比、Top/Bottom 排名 |
| 堆叠柱图 | 类别 + 少量子类别 + 数值 | 结构随分组变化 |
| 饼图/环图 | 2-6 个互斥类别、总量有意义 | 构成占比 |
| 散点图 | 两个数值字段、样本量足够 | 两项指标的关联提示 |
| 直方图/箱线图 | 一个数值字段、样本量足够 | 分布、离群提示 |

图表规划必须保存标题、类型、分类字段、数值字段、聚合、筛选、排序、单位和数量合同。饼/环图不能
用于时间趋势，类别过多时必须改为 Top N 条形图；散点图只能说“关联提示”，不能输出因果结论。

### 6.3 结果与交付

- 独立“图表看板”结果页以稳定网格展示图表卡；卡片固定画布比例，避免加载后跳动。
- 每张卡展示标题、结论一句、数据范围、图例和三个图标操作：查看数据、保存 PNG、加入 Excel 交付。
- 已选择图表可一次确认生成；PNG 写入 `output/data_charts/`，同名新建、不覆盖源文件。
- Excel 交付仍写入 `output/data_analysis/`，其中使用相同 chart contract 的原生图表；PNG 不冒充 Excel
  图表对象。
- 图表渲染、PNG 文件存在性/尺寸、数据点范围和任务 artifact 必须回读验证。历史页只显示受控 URI、
  名称、时间和验证摘要，并提供既有安全打开入口，不显示绝对路径。

**D5.2 当前 MVP 已实现：**客户先在 D2 预览中查看聚合表与图表合同，再明确确认“生成 PNG 看板”；
后台只重算同一份白名单聚合表，写入 `output/data_charts/<task_id>/`，并以 Pillow 回读 PNG 格式、
尺寸与字节大小。Qt 以独立看板窗口显示左侧图表清单和右侧大图预览，图像字节经受控 HTTP 接口异步
读取；历史只保存脱敏 artifact、类型、尺寸和验证摘要。当前一次交付最多 4 张 D2 支持的 bar/line/
pie/doughnut 图，不做自由筛选、钻取、单卡再编辑或 WebEngine 交互图，这些能力须在未来单独确认。

**连续测量数据优先规则：**字段画像若同时识别出“位置/序号/轮次”等连续数值横轴，以及“清晰度、
评分、质量、响应”等数值指标，默认先生成一张按横轴排序、同位置取均值的折线图。此时不为凑数量
自动附带类别柱图；只有客户明确提出比较、分组、构成或占比时才追加对应图表。模型可以解释已验证
结果或重排 L1 候选，但不接收整份 CSV，更不能臆造图表数值。

### 6.4 视觉与性能

- 图表采用色盲安全色板、清晰中文字体、有限颜色、充足标签留白和必要的数据单位；不使用炫光、
  无意义渐变或伪 3D。
- 图表按单张后台渲染并发布真实阶段；一张失败只标记该卡，不撤销已完成图表。
- Qt 首版以已验证 PNG 预览为主，避免为了交互图引入 WebEngine 或在 UI 线程绘图；未来筛选/钻取应
  重新发起受控计算，不把未验证数据缓存在界面中。

### 6.5 验收

- 对日期销售表，能交付折线和条形图；对区域构成表，能交付条形图和适用的环图；
- 客户明确要求的图表数量与类型形成硬合同，无法满足时显示缺口而非静默少交付；
- 每张 PNG 与其图表合同、聚合表和历史 artifact 一致；源文件字节保持不变；
- 窄窗口、折叠左导航和长标题下，卡片、操作和状态不重叠。

## 7. 路径 C：安全字段加工与数据副本

### 7.1 客户价值

解决“这张表能看，但还缺一列才能真正使用”。客户只表达业务意图，如“按日期拆月份”“计算金额”
“给成绩分档”，系统把它翻译为有限、可预览的字段变更，而不是让客户写公式或允许模型执行代码。

### 7.2 初版允许操作

| 操作 | 示例 | 约束 |
| --- | --- | --- |
| 四则计算/比率 | 金额 = 单价 × 数量；毛利率 = 毛利 ÷ 收入 | 仅明确数值列，除零产生空值并计数 |
| 日期拆分 | 从日期生成年、月、季度、星期 | 仅高置信日期列 |
| 数值保留位数 | 金额保留 0 至 6 位小数 | 只在副本中新建列；展示保留两位不改变原始计算精度 |
| 排名与占比 | 按金额排名；计算类别占比 | 必须说明分组与排序范围 |
| 分段标签 | 成绩分为优秀/合格；金额分区间 | 边界和标签在预览中明确显示 |
| 累计、环比与环比百分比 | 月度累计；相邻月份差值/变化率 | 必须有稳定日期顺序与数值列；首行和上一期为零明确留空 |
| 文本轻清洗 | 去首尾空格、统一空值、稳定表头 | 沿用既有 `safe` 清洗规则 |

不支持任意 Excel 公式、宏/VBA、自由 Python/SQL、跨文件查找、模糊匹配合并、自动删除行或直接覆写
客户文件。无法映射到上述操作时，系统必须解释当前不支持的原因，并给出可手动补充的字段条件。

### 7.3 预览、确认与产物

1. 客户在字段向导中选择操作、字段和有限参数；字段加工不接收自然语言来执行或生成公式。
2. 本地规则构造 `DataTransformPlan`：源列、受限操作、参数、新字段名和理由；不调用 LLM。
3. Validator 校验字段、类型、名称冲突、除零/日期解析风险与行数影响。
4. 本地 Tool 在内存中计算，展示字段定义、影响行数、前后有限预览和警告。
5. 客户确认后，新建与输入类型一致的副本到 `output/data_transformations/`：CSV 输出 UTF-8 BOM CSV，
   XLSX 输出仅含一个“数据副本”工作表的普通 XLSX。标准记录型表保持原行列方向，并把选中的派生字段
   追加在原字段之后；不创建说明页、分析页、Excel Table 或视觉样式。随后重新打开验证字段与行数。
6. 结果登记为 artifact。客户可以把该新副本作为下一次数据工作台材料导入，原 CSV/XLSX 永不修改。

### 7.4 验收

- “单价乘数量”“按日期取月份”“按金额排名”三类意图都能得到受限计划、预览和经回读的新副本；
- 非数值相乘、未知列、零除、字段重名和日期解析不足均有可理解错误或局部空值警告；
- 未确认不写文件，确认后只产生一个同类型、无额外样式的新副本，历史能定位操作摘要和 artifact；
- 模型不可用时，客户仍可从有限模板完成上述常见操作。

### 7.5 当前实现与验收状态

D5.3 MVP 已完成工程实现与离线回归，当前在 Qt 本机交互验收阶段。入口复用既有结果阅读，客户先执行
“生成分析预览 -> 查看预览 -> 字段加工”，再在独立向导中选择有限操作和字段；不会把设置、预览、日志
和长表格塞进主工作台。实际支持四则计算、日期拆分、数值保留位数、排名、占比、分段、累计、环比、环比百分比和文本首尾空格清理。

- **2026-08-17 客户反馈修正：**画像 HTTP 404 曾由 Qt 对含中文、空格或括号的文件名重复路径编码引起；
  客户端现在只交给 `QUrl` 自然文件名，并在后端工作区副本缺失时自动刷新一次列表。刷新仍找不到时，界面
  只提示“需要重新导入”，不暴露 HTTP 术语，也不循环请求。离线回归覆盖一次正确编码的路径段。
- 字段加工入口已从动态拼接控件迁为 Qt Designer 独立工作台：左侧只选一种受限操作，右侧按需出现字段和
  参数，主页面不再承载这些设置。客户可把最多 12 项操作加入同一队列，统一预览后只生成一个新副本；
  每项仍只引用画像中的原字段，不允许隐藏的公式链或覆盖已有字段。已移除鸡肋的“智能推荐”；创建副本
  完全是选项驱动的本地功能，D2 的一句目标只用于分析问题而不驱动字段加工。队列、预览、导出、回读和
  artifact 元数据均保留全部新增字段，不再只显示第一项。
- 字段副本、Excel 分析和 PNG 图表的主阅读入口始终是应用内的预览/看板与任务历史，不要求客户去
  `output/` 找结论。写入成功后，客户端仅通过后端的受控 artifact 打开接口交给系统默认程序打开文件；
  绝对输出路径不回传 Qt，历史中的新 runtime artifact 同样可打开。

- 所有预览均在内存中完成，并显示新增字段、完整表作用域、影响行数、空结果、最多 12 行样例和风险提示；
  未确认前不创建文件。
- 已确认任务走 `202 -> 事件流 -> 终态补读`，只新建 `output/data_transformations/` 下与源文件同类型的
  副本。CSV 保持 CSV；XLSX 只含无样式的“数据副本”单表。写完后重新打开核对类型、字段与行数；操作
  说明和溯源留在任务历史，而不污染客户可继续使用的数据表。
- 加工不调用模型、不联网、不执行公式、脚本或宏；源 CSV/XLSX 从不改写。历史只保存脱敏操作、统计和
  artifact 元数据，绝对输出路径不展示；取消会清理尚未登记的副本，历史任务不能一键重放旧数据版本。
- 当前累计与环比的范围是“全表按所选日期字段升序，同日期保留源行顺序”，不隐含分组；分段会在预览中
  显示边界。需要分组累计、跨表关联或自定义公式时必须另立客户任务与安全规格。
- 当前“追加字段”面向常见的记录型表：首行是字段名、每行是一条记录。若客户材料本身是“第一列为字段名、
  后续列为值”的转置键值布局，不能把它误当普通列加工；该“向下追加派生行”的映射、预览和验收将作为
  后续小闭环单独设计，当前明确提示而不静默改写布局。

## 8. Qt 信息架构

数据工作台继续使用现有一级导航，不新增营销式子 Agent。页面采用“当前任务工作台 + 独立结果阅读”
而不是把导入、设置、长结论、图表、日志和产物挤在同一屏。

```text
准备页：导入材料 -> 文件画像 -> 一句目标/动态示例 -> 开始
运行页：真实阶段、当前数据范围、取消
结果页：概览 | 推荐分析 | 图表看板 | 字段加工 | 交付与历史
```

- 准备页首屏优先显示文件状态和下一步，不保留大面积空 Hero；`? 使用说明` 必须是可见按钮，字段和
  有限行预览默认收进“字段详情”。
- 一句目标与“开始分析”是当前工作台最底部的行动区；结果、字段详情或历史展开后仍不应把输入挤到
  文件选择区中间。超时或空的“下一步建议”不是主页面内容，不得占用结果区域。
- 结果页的 `概览` 只呈现规模、质量问题、已完成成果和下一步建议；详细表格、图表数据范围、计划和
  任务审计进入对应 tab 或详情窗。
- 图表、派生字段和导出都使用 Preview -> Confirm -> Execute；写入确认说明新增内容、输出类别和
  原文件不变，不弹出不必要的多层对话框。
- 主工作台在预览完成后直接展示“本次结论”的标题、正文和依据说明；独立详情顶部再展示完整发现、下钻建议
  与证据范围。可用模型时只能依据已验证事实底稿、指标、聚合表和图表合同返回严格 JSON；模型超时、格式错误、
  无数据锚点或越界时自动回落到本地确定性结论，不能留下空白结果区。
- 图表看板使用系统标题栏的最大化/还原按钮；图像始终按当前窗口的可用区域等比自适应，完整显示而不再
  让客户手动选择倍率或拖动图片。
- 按钮必须有默认、禁用、运行、成功、部分完成和失败状态；无确定进度时显示真实阶段，不伪造百分比。
- 左侧导航折叠后保留 Tooltip；主要点击目标约 40px；键盘焦点和文本状态必须可见。
- 动效只用于页/面板切换、图表卡出现和成功反馈，时长短、可打断、可降低，不影响计算和关闭窗口。

## 9. 任务、artifact 与失败恢复

新增结果必须复用现有 Runtime 任务、WebSocket 阶段、取消、artifact resolver 和历史页；不为 PNG 或
字段副本另建一套历史系统。

| 产物 | 目录 | 历史显示 |
| --- | --- | --- |
| 可编辑 Excel 分析 | `output/data_analysis/` | 表/图数量、验证摘要、受控打开 |
| 图表 PNG | `output/data_charts/` | 图表类型、范围摘要、尺寸、受控打开 |
| 字段加工副本 | `output/data_transformations/` | CSV 或普通单表 XLSX；新字段、影响行数、验证摘要、受控打开 |

失败、取消和部分完成必须保留已完成范围。例如四张图中一张不可渲染时，三张已验证 PNG 可以交付，
第四张清楚说明失败字段/原因；未通过回读的文件不能登记 artifact。任务历史不保存完整表格或原始行，
只保存脱敏结构、数据范围、操作合同、统计数量、输出元数据和错误原因。

## 10. 分阶段实现与验收门槛

| 阶段 | 范围 | 前置 | 完成定义 |
| --- | --- | --- | --- |
| D5.0 | 产品规格、CSV 兼容回归、Qt 信息架构审查 | D1-D4 基线 | 仅本文件完成，不算功能实现 |
| D5.1 | 路径 A：本地推荐 + 可选 L1 模型排序 | D5.0、独立确认 | **已完成**：推荐能转为白名单计划，模型失败可降级 |
| D5.2 | 路径 B：图表看板、PNG、历史 artifact | D5.1、独立确认 | **已完成 MVP**：真实数据计算、PNG 回读、独立看板与历史可见 |
| D5.3 | 路径 C：字段加工预览与新副本 | D5.2、独立确认 | **已完成工程 MVP，客户反馈修正已通过技术验证，待 Qt 客户复验**：十类受限操作、确认写入、回读与源文件不变 |
| D5.4 | Commander 单数据集只读准入 | D5.1-D5.3 稳定 | **已完成工程 MVP，待 Qt 客户复核**：只接受一份显式绑定的已导入 CSV/XLSX；创建可审计子任务，复用 D2 本地计算，仅回传结论、源哈希和统计数量；不保存原始/预览行，不生成或修改文件。`data_agent.runtime_ready=true` 仅代表这一 action 可执行。 |

每一阶段必须先通过离线回归、实际 `.venv` 依赖检查、相关 artifact 回读和 Qt 可见验收，再进入下一项。
修改 C++ 或 `.ui` 时必须使用 Qt Creator 实际 MSVC/JOM 构建环境；没有 C++ 改动时不为文档或 Python
改动重复消耗 Qt 构建时间。

## 11. 明确暂缓与后续候选

- 多文件/多工作表关联、数据库与 SaaS 连接、MCP、联网补数、预测和自动经营决策；
- 直接编辑客户源文件、任意公式、VBA、脚本和运行模型生成代码；
- L3 原始数据外发、企业敏感数据策略、行业合规模板；
- 高价值候选“同结构新旧文件对比 + 可复用分析配方”：适合周报/月报和持续导出场景，但需要版本
  匹配、字段映射、差异合同和新的隐私评审，不能混入 D5；
- 学生问卷/实验、销售运营、费用台账等行业配方：先以核心路径验证共性，再逐项讨论，不按人群名称
  批量新增 Agent。
